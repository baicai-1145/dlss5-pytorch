## 3. 131,072B down-proj 区解码分析

- 字节: 131,072 = 65,536 fp16 值 (1B/2B = 2 字节/值)
- 等价候选形状: (256,256), (512,128), (128,512), (32,2048), (64,1024) — 全部 65,536 值
- 第一 32 值: 范围 [0.6641, 0.9980], mean **0.9715** → **LN gamma 表 (32 channels)**
- 第 33-64 值: 范围 [-0.009888, 0.007889], mean -0.000082 → bias/小权重
- 第 65-65536 值 (65,472 个): mean=-0.000013, std=0.003753, absmax=0.0629

**decisive 结论**: 
- 131,072B 是 **fp16 down-proj/refinement 矩阵** (不是 E4M3, 因为窗口分类为 E 但 fp16 解码合理)
- 前 32 fp16 = **c=32 LN gamma** (mean 0.97, range 0.66-1.0) — 用于 c=32 通道 sub-tensor (可能对应 c=512 split-swin 的 16 heads × 2 = 32 个 gate)
- 后 65,504 fp16 = **down-proj 主体** (std ≈ 0.003, absmax 0.99 — 标准小幅度初始化)
- 形状最可能 **(256, 256) fp16** (down-proj 但只有 256 输出通道 — 需配合其他机制扩到 512)
- **不符合** 标准 512×256 E4M3 down-proj (那需要 131,072B 但 std=0.06 不是 2.27)
- 不符合标准 512×128, 512×256 等 — 因为整区域被 fp16 解码器统一处理

## 4. 与 b15 (c=256 标准块) 对比

**结论**: b22 的 c=256 swin block 是**简化版** (无复杂 MX scale 行), 用 [689152:820224] 这 131,072B 装了 down-proj。

## 6. 总体结论

**b22 = [c=256 SwinBlock (689,152B 简化版)] + [c=256→c=512 down-proj/refinement in fp16 (131,072B)] + [60B 杂项]**

关键事实:
1. b22 共 **820,288B** = 689,152B (c=256 swin 简化版) + 131,072B (down-proj fp16) + 60B (tail)
2. **131,072B 转换区解码为 fp16** (65,536 个 fp16 值), std=0.02, absmax=0.99 — 典型小幅度 fp16 权重
3. 转换区前 32 fp16 值 = c=32 LN gamma 表 (mean 0.97)
4. 形状最可能 (256, 256) — **不是标准 512×256 down-proj**, 而是 256→256 refinement 或 256→512 split down-proj 的前半
5. 完整 256→512 down-proj 可能跨 b22 (前半 256×256) + b23.layer1 (proj 512×512) 拼接实现, 或者 256→256 + concat 复制
6. b22 c=256 部分比 b15 短 80B — **b22 是简化 swin 块** (无复杂 MX scale 行分布), 与其在 c=256→c=512 转换处的角色一致
